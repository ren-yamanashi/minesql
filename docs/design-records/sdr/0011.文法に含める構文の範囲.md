# 文法に含める構文の範囲

## Motivation

MySQL の構文規則に従う ([SDR-0007](./0007.SQLパーサーはMySQLの構文規則に従う.md)) と決めても、MineSQL が実装しない機能の構文をどう扱うかは別の問題として残る。パーサーだけ MySQL と同じに受理して後段で「未対応」と返すのか、文法から外して構文エラーにするのかを決める必要があった。あわせて、「やらないこと」(issue #120) に挙がっていた機能のうち、いくつかは含める価値があるかを見直した

## Decisions

- MineSQL が実装していない機能の構文は、文法に含めず構文エラーにする
  - 含めるかどうかは「実装コスト」と「MySQL の仕組みを説明するうえでの重要度」で個別に判断する
- 含めないもの: GROUP BY / HAVING / 集約関数 / LEFT・RIGHT JOIN / UNION / NULL / 関数呼び出し / VARCHAR と INT 以外の型 ([SDR-0023](./0023.データ型はVARCHARとINTを持つ.md)) / TEMPORARY / テーブルオプション
- 対応する機能とあわせて含めるもの
  - SELECT の ORDER BY と LIMIT (issue #120 の「やらないこと」から外した)
  - ファイルソート (ORDER BY をインデックスの順序で満たせないときのソートで、ソートバッファ内のソートと、収まらない場合のディスクへの書き出しとマージを含む)
  - `START TRANSACTION WITH CONSISTENT SNAPSHOT`
  - `SELECT ... FOR UPDATE` と `SELECT ... FOR SHARE` (`LOCK IN SHARE MODE` は同義語)
  - アカウント管理ステートメント `CREATE USER` / `ALTER USER` / `DROP USER` と、権限の `GRANT` / `REVOKE` ([SDR-0017](./0017.アカウント管理ステートメントを対象に含める.md)、[SDR-0018](./0018.権限はグローバル権限だけを持つ.md))
    - 採るのは `IDENTIFIED BY` と `ON *.*` の形だけで、`IDENTIFIED WITH`、多要素認証、`ACCOUNT LOCK` / `PASSWORD EXPIRE`、`IF [NOT] EXISTS`、`ON db.*` / `ON db.tbl`、カラムリスト、ロールは外す
  - `KILL [CONNECTION] id` ([SDR-0027](./0027.KILLステートメントを対象に含める.md))
- UPDATE / DELETE の `ORDER BY ... LIMIT` は含めない

## Context

### 文法から外す理由

パーサーが受理する構文と、実行できる機能を一致させたい。MySQL の規則どおりに受理して後段で拒否する案は、誰も消費しない AST のノードと、プリペア側の拒否処理が要る。本の中心は InnoDB (ストレージ) になる見込みで、外す構文の重要度は高くないと判断した

外した構文は詳細仕様に MySQL の規則の permalink つきで記録してある。後から含めると決めたら、表の行を「採用」に変えて規則を写せばよい

### 例外として含めた理由

ORDER BY / LIMIT、ファイルソート、`WITH CONSISTENT SNAPSHOT`、`FOR UPDATE` / `FOR SHARE` の 4 つは、いずれも実装が小さく、本で説明したい仕組みに直結する

- LIMIT は件数のカウンタで済む
- ORDER BY は、インデックスの順序で済ませるかソートするかというオプティマイザの判断の題材になる
  - ファイルソートを持たないと、インデックスで満たせない ORDER BY をエラーにするしかなく、説明の負担にしかならない
- `WITH CONSISTENT SNAPSHOT` はトランザクション開始時に ReadView を作る操作で、MVCC の説明に直結する
- `FOR UPDATE` / `FOR SHARE` は読み取り時に排他ロック / 共有ロックを取る操作で、ロックの説明に直結する

アカウント管理ステートメントと `GRANT` / `REVOKE` は、アカウントと権限を対象に含めた判断 ([SDR-0017](./0017.アカウント管理ステートメントを対象に含める.md)、[SDR-0018](./0018.権限はグローバル権限だけを持つ.md)) に付随して含めた。採る形を最小にする理由はそれぞれの SDR に書いた

UPDATE / DELETE の `ORDER BY ... LIMIT` は標準 SQL にない MySQL 拡張で、用途が運用寄り (一括削除を小分けにするなど) である。含めるには、更新・削除の経路に「並べて絞った行を渡す」実装を別に足す必要があるので含めない
