# アカウント管理ステートメントを対象に含める

## Motivation

認証の方式 ([SDR-0015](./0015.認証の方式.md)) では、扱うアカウントを初期アカウントだけにし、アカウントの作成・変更・削除を対象外にしていた。認証の要件を MySQL の設計文書 (WL) に沿って整理する過程で、アカウントの管理は MySQL の認証の仕組みから切り離せない部分だと分かり、対象に含めるかを改めて決める必要が生じた

## Decisions

- アカウント管理ステートメントを対象に含める
  - `CREATE USER user IDENTIFIED BY 'password'`
  - `ALTER USER user IDENTIFIED BY 'password'`
  - `DROP USER user`
- `user` は `'名前'@'ホスト'` の形を受理するが、ホストは `%` だけを認め、`@ホスト` を省略した場合も `%` とする (MySQL の既定と同じ)
  - `minesql.user` はホストの列を持ち、MySQL と同じくホストと名前の組でアカウントを識別する (`%` だけに限るのは当面の判断で、列は残す: 2026-09-30 確定)
- 文法は最小にする
  - 採らない句: `IDENTIFIED WITH`、`RANDOM PASSWORD`、多要素認証、`ACCOUNT LOCK`、`PASSWORD EXPIRE`、`REQUIRE`、リソース制限、`IF [NOT] EXISTS`
  - 採らないステートメント: `SET PASSWORD`、`RENAME USER`
- 資格情報の変更 (`ALTER USER`) とアカウントの削除 (`DROP USER`) は、そのアカウントの SHA256 パスワードキャッシュのエントリを消す
- 初期アカウントは bootstrap で `CREATE USER` ステートメントにより作る (権限の付与は [SDR-0018](./0018.権限はグローバル権限だけを持つ.md))
  - 名前は `root`、ホストは `%` に固定し、パスワードはサーバーが乱数で生成してログに出力する (MySQL の `--initialize` と同じ形: 2026-09-30 確定)
  - MySQL と違い、初期化は別のモードではなく初回の起動の中で行い、パスワードの期限を持たないので最初のログインでの変更は強制せず、パスワードなしの初期化 (`--initialize-insecure` 相当) は持たない
- 誰がアカウント管理ステートメントを実行できるかは権限で決める ([SDR-0018](./0018.権限はグローバル権限だけを持つ.md))

## Context

### MySQL のアカウント管理ステートメントは 1 つの経路で動く

MySQL では、`CREATE USER` から `DROP USER` までのアカウント管理ステートメントが同じ経路を通る。認証プラグインが認証文字列を生成し、`mysql.user` に行を書き、メモリ上の ACL キャッシュを更新し、認証系へ通知する。X Plugin はこの通知を受けて SHA256 パスワードキャッシュのエントリを消す。文の末尾で暗黙にコミットし、失敗すればロールバックしてテーブルとメモリの整合を保つ

初期アカウント (`root@localhost` や `mysql.session@localhost`) も、この経路の外で作られるのではなく、初期化時に同じ `CREATE USER` ステートメントで作られる

### 初期アカウントだけにする案を改める理由

旧決定では、この経路を持たず、bootstrap が直接アカウントを投入するだけだった。認証を持つのにアカウントを増やす手段がないのは、認証の機能として不完全である。アカウント管理ステートメントを含めれば、本で「DDL がシステムテーブルの行になり、認証がそれを読む」という書き込み側も示せ、キャッシュの無効化 ([WL#10992](https://dev.mysql.com/worklog/task/?id=10992) の要件) も実際に動く

MineSQL は ACL キャッシュを持たない ([SDR-0015](./0015.認証の方式.md)) ので、アカウント管理ステートメントの実装は「システムテーブルへの行の書き込み」と「キャッシュのエントリの削除」で済み、MySQL より単純になる

### 文法を最小にする理由

MySQL の `CREATE USER` の規則は多要素認証やパスワードの期限まで含む。採らない句はいずれも実装しない機能 (アカウントのロック、期限、TLS 要件、複数の認証要素) に付随するので、「実装しない機能の構文は文法に含めない」([SDR-0011](./0011.文法に含める構文の範囲.md)) に従って外す

### 権限と同時に決めた理由

権限を持たないままアカウント管理ステートメントを入れると、認証済みのアカウントなら誰でもアカウントを作り消せる状態になる。MySQL は `CREATE USER` 権限を要求する。このため、アカウント管理ステートメントと権限 ([SDR-0018](./0018.権限はグローバル権限だけを持つ.md)) は 1 組として決めた

### 後から広げるとき

`SET PASSWORD` / `RENAME USER` / `IF EXISTS` を後から入れる場合、キャッシュのエントリを消す対象が増えるだけで、照合側は変わらない。ホストのパターン (`192.168.1.%` など) を後から認める場合は、ホストの列は既にあるので、値の検査を緩めることと、照合で接続元をパターンと比べることが増える
