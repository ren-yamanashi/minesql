# 型の規則は MySQL に合わせ、小数は浮動小数点で持つ

## Motivation

カラムの型を `VARCHAR` と `INT` の 2 つにした ([SDR-0023](./0023.データ型はVARCHARとINTを持つ.md)) ことで、型が混ざる比較・算術・代入をどう扱うかを決める必要が出た。あわせて、文法は整数のほかに小数と指数表記のリテラルも受理する ([005_parser/reference/sql_parser_spec.md](../../specification/005_parser/reference/sql_parser_spec.md) の「数値」) ため、それらをどの内部の型で扱うかも決める必要があった

## Decisions

- 式の値の内部の型は、整数 (符号付き 64 ビット)、浮動小数点 (倍精度)、文字列の 3 つにする
  - 整数リテラルは整数、小数と指数表記のリテラルは浮動小数点、文字列リテラルは文字列
  - 符号付き 64 ビットに収まらない整数リテラルは浮動小数点にする
  - `INT` カラムの値は整数、`VARCHAR` カラムの値は文字列
- 比較の型は MySQL の規則に合わせる
  - 両辺が同じ型ならその型で比べる (文字列どうしは文字列として、整数どうしは整数として)
  - 型が違えば両辺を浮動小数点にして比べる
  - 文字列を数値に読めなければ 0 として扱い、警告を出す
- 算術とビット演算の型は MySQL の規則に合わせる
  - 整数どうしの `+` `-` `*` `%` (`MOD`) と `DIV` は 64 ビット整数で計算し、収まらなければエラー
  - 浮動小数点か文字列が混ざれば浮動小数点で計算する (文字列は数値に読み、読めなければ 0 として扱い、警告を出す)
  - `/` は常に浮動小数点で計算する
  - ビット演算 (`|` `&` `^` `<<` `>>` `~`) は両辺を整数にして 64 ビットで計算する
- 代入 (INSERT / UPDATE) は値をカラムの型に変換する
  - `INT` カラムへの文字列は数値に読み、読めなければエラーにする (整数の範囲に収まらない値もエラー)
  - `VARCHAR` カラムへの数値は文字列にし、宣言した長さを超えればエラーにする
  - 警告ではなくエラーにするのは、既定の sql_mode が strict である ([SDR-0013](./0013.sql_modeの既定値に固定し非推奨と無視される構文は採らない.md)) ことによる
- 式の型はプリペアで決め、値の変換とその警告・エラーは実行の段階で起きる

## Context

### MySQL の規則に合わせる理由

型が違う比較を浮動小数点で行う規則と、その結果として文字列カラムと数値の比較でインデックスが使えなくなる振る舞いは、MySQL の型変換の中心で、本で扱う価値がある。型が違えばエラーにする案は、利用者が誤りにくい代わりに示せるものが少ない。リテラルだけ相手の型に変換する案は、MySQL とも異なる第 3 の意味論になる。MySQL の規則は小数と浮動小数点を既に含むので、型を後から足しても形が変わらない

### 小数を浮動小数点で持つ理由

MySQL は小数リテラルを 10 進 (正確な値) で持ち、比較の型も「整数と 10 進の組は 10 進」と分ける。MineSQL には 10 進のカラムがなく、10 進が現れるのはリテラルだけである。一方、浮動小数点の比較は型が違う比較のために必ず要る。ワイヤ形式も、浮動小数点はプロトコルバッファの double そのものだが、10 進はスケールと BCD と符号を並べた独自の符号化になる。使い道の狭い型のために 10 進の算術と符号化を持つより、小数を浮動小数点として扱う方が妥当である

### MySQL との差

- 小数リテラルを含む式: 次の 3 つで差が出る
  - 有効数字が 16 桁を超える小数リテラルとの比較
  - 小数どうしの算術の結果 (`0.1 + 0.2` は MySQL が 0.3、MineSQL が 0.30000000000000004)
  - 結果カラムのワイヤ上の型 (MySQL は DECIMAL、MineSQL は DOUBLE)
- 整数どうしの `/`: MySQL は 10 進 (`7 / 2` は 3.5000)、MineSQL は浮動小数点 (3.5)
- 符号付き 64 ビットに収まらない整数リテラル: MySQL は符号なし整数として扱うが、MineSQL は `UNSIGNED` を持たないので浮動小数点にする
- ビット演算の結果: MySQL は符号なし 64 ビットで返すが、MineSQL は符号付き 64 ビットで返す

### 後から広げるとき何が変わるか

- 10 進 (DECIMAL): 内部の型を足し、比較の型を MySQL の 4 分類 (整数、10 進、浮動小数点、文字列) に戻し、ワイヤ上の BCD の符号化を足す
- `UNSIGNED`: 整数の内部の型に符号なしを足し、比較と算術の場合分けを増やす
- 日時など他の型: リテラルの形と、型ごとの変換の規則を足す
