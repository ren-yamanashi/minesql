# 管理コマンドは接続系と Notice 系の 6 つを実装する

## Motivation

X Protocol の `StmtExecute` には、SQL ではなく X Plugin 自身へのコマンドを送る経路 (`mysqlx` namespace の管理コマンド) がある。MySQL 8.4 には 14 個あり、どれを実装するかを決める必要があった

## Decisions

- 接続に関する 3 つ (`ping` / `list_clients` / `kill_client`) と、Notice に関する 3 つ (`enable_notices` / `disable_notices` / `list_notices`) の計 6 つを実装する
- コレクションに関する 8 つ (`create_collection` / `drop_collection` / `ensure_collection` / `modify_collection_options` / `get_collection_options` / `create_collection_index` / `drop_collection_index` / `list_objects`) は実装しない

## Context

14 個は性格で 3 つに分かれる

- 接続系: 生存確認、接続の一覧、他の接続の強制切断
  - コネクションハンドラーが持つ接続一覧と kill の経路をそのまま使う
- Notice 系: 「どの種類の Notice を送るか」をセッション単位で切り替える
  - 実装はセッションごとのフラグで済み、Notice の仕組みそのものには手を入れない
- コレクション系: ドキュメントモデルの管理コマンド

コレクション系は [SDR-0002](./0002.ドキュメントモデルは実装しない.md) に従って外れる。Notice 系の設定がなくても、`ROWS_AFFECTED` や `ServerHello` のような Notice は送られるので、Notice の機能は成り立つ。それでも入れるのは、警告の Notice を実装するなら、それを止める手段も要るためである
