# SQL パーサーは MySQL の構文規則に従う

## Motivation

SQL パーサーを作る前に、受理する構文を「MineSQL が扱える最小の SQL」として独自に決めるのか、MySQL が受理する構文に合わせるのかを決める必要があった。この選択は文法の書き方だけでなく、公式のクライアントや利用者が書いた SQL がそのまま通るかどうかを左右する

## Decisions

- 対応するステートメントについては、MySQL の構文規則にできるだけ従う
  - `sql_yacc.yy` の対応する規則、字句規則 (識別子、リテラル、コメント)、演算子の優先順位を写す
- 従う意味がない構文は受理しない
  - 実装しない機能に付随する句、後方互換のためだけの別表記
  - どこを外したかは、理由つきで詳細仕様に記録する
- サブクエリは対応しない (issue #120)

## Context

「小さい MySQL」であることが外から見える条件は、MySQL の常識どおりに書いた SQL をそのまま受理できることである。独自に最小の SQL を決めると、`INNER JOIN` と `JOIN` のような同義語、`VALUE` と `VALUES` のような揺れ、コメントや引用の細部で、利用者は MineSQL 固有の癖を覚えなければならない

MySQL の規則を写す方針には、もう 1 つ利点がある。文法を規則単位で MySQL と比べられるので、「どこを写し、どこを外したか」を行単位で記録でき、後から機能を足すときも対応する規則を写せばよい
