# Expect ブロックを実装する

## Motivation

X Protocol では、クライアントは前の応答を待たずに次のリクエストを送ってよい (パイプライン化)。すると「前のリクエストが失敗したら、後続は実行してほしくない」という要求が生まれる。これを扱うのが Expect ブロック (`Mysqlx.Expect.Open` / `Close`) で、実装するかどうかを決める必要があった

## Decisions

- Expect ブロックを実装する
- 条件は `no_error` (ブロック内で 1 つでも失敗したら、以降を実行せずに失敗させる) だけを持つ

## Context

パイプライン化は X Protocol の主要な特徴で、これを活かすには依存関係のあるリクエストの失敗を扱う手段が要る。Expect ブロックはそのための仕組みであり、これがないとクライアントは結局 1 つずつ応答を待つしかない

一方で実装は小さい。セッションごとに「開いているブロックの入れ子」をスタックで持ち、リクエストのたびに「失敗中のブロックの中か」を判定するだけである。プロトコルの定義にある他の条件は、機能検出向けとドキュメントモデル向けなので対象外にできる
