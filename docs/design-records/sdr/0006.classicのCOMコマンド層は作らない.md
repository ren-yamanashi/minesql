# classic の COM コマンド層は作らない

## Motivation

MySQL のサーバー本体には、classic protocol のコマンド種別 (`COM_QUERY` や `COM_INIT_DB` など) ごとに処理を振り分ける層 (`dispatch_command`) がある。X Plugin は自分では SQL を実行できないので、受け取ったリクエストをこのコマンド種別に翻訳して本体に頼んでいる。MineSQL にこの層を作るかどうかを決める必要があった

## Decisions

- classic のコマンド種別と、それを振り分ける層は作らない
- コマンドディスパッチャは内部セッションに直接依頼する
- 仕様書では委譲先を「内部セッション」と書き、MySQL でのコマンド種別への翻訳は詳細仕様の 1 節にとどめる

## Context

X Plugin がコマンド種別の層を使っているのは、サーバー本体がプラグインに提供している呼び出し口がそれしかないからである。頼んでいる操作は、文の実行、セッション状態のリセット、デフォルトスキーマの切り替え、プリペアド系の 4 種類で、いずれも「内部セッションにやってほしいこと」を classic の語彙に言い換えたものである

classic protocol を持たない MineSQL ([SDR-0001](./0001.実装対象はXProtocolに従うサーバー.md)) では、この言い換えの層に意味がない。ディスパッチャが内部セッションを直接呼ぶ方が、層が 1 つ減って流れも追いやすい
