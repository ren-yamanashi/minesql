# autocommit は常に有効で、セッション変数は持たない

## Motivation

内部セッションのトランザクションの状態を書くとき、トランザクションが「進行中」になる経路を決める必要があった。MySQL では `BEGIN` / `START TRANSACTION` のほかに、`autocommit=0` のときに最初のステートメントが暗黙に始める経路がある。`autocommit` はセッション変数で、`SET` のほかにサーバーの設定 (設定ファイル、`SET GLOBAL`) でも既定値を変えられるため、文法に `SET` がないだけでは「`autocommit=0` にならない」とは言えなかった

## Decisions

- `autocommit` は常に有効 (1) で、変える手段を持たない
  - セッション変数を持たず、文法に `SET` を含めない
  - サーバーの設定 (設定ファイル、起動オプション) でも `autocommit` を変えられない
- トランザクションが「進行中」になるのは `BEGIN` / `START TRANSACTION` で始めたときだけ
- `COMMIT` / `ROLLBACK` の後に次のトランザクションが暗黙に始まることもない

## Context

### 持たない理由

本で示したいのは、明示的な `BEGIN` / `COMMIT` と、DDL などの暗黙のコミットの関係である。`autocommit=0` は「`BEGIN` なしで最初のステートメントが始め、`COMMIT` の直後に次が始まる」という経路を重ねるもので、説明が増える割に、見せられる仕組み (トランザクションの開始と確定) は変わらない

セッション変数を持たないのはこの判断の帰結でもある。`autocommit` を変えられないなら `SET` を持つ意味がなく、ほかのセッション変数 (`sql_mode` は既定値に固定、`max_execution_time` は中断の経路を持たない) も使い道がない

### 後から広げるとき何が変わるか

- セッション変数: 内部セッションの実行コンテキストに変数の表を足し、文法に `SET` を足す
- `autocommit=0`: トランザクションの状態に「暗黙に始まった」を足し、`COMMIT` / `ROLLBACK` の後に次を始める処理と、サーバーの設定からの既定値の読み込みを足す
