# プロトコルのプリペアドステートメントとカーソルは実装しない

## Motivation

X Protocol には、SQL を事前に登録しておいて後から引数だけを送って実行する「プリペアドステートメント」(`Mysqlx.Prepare`) と、結果を少しずつ取り出す「カーソル」(`Mysqlx.Cursor`) がある。プロトコルを実装する前に、これらを持つかどうかを決める必要があった

## Decisions

- `Mysqlx.Prepare` と `Mysqlx.Cursor` のメッセージは実装しない
- 受け取ったときは未対応のメッセージとしてエラーを返す
- 「やらないこと」の一覧 (issue #120) にも記載する

## Context

プリペアドステートメントは往復回数を減らすための最適化機能で、クライアントは `StmtExecute` を毎回送れば同じ操作ができる。カーソルはプリペアドステートメントの結果を分割して取り出す仕組みなので、プリペアドステートメントを持たなければカーソルも成り立たない

紛らわしい点が 1 つある。仕様書の `prepare/` の「プリペア」は、ステートメントを実行できる状態に整える段階 (名前解決と型決定) で、プロトコルのプリペアドステートメントとは違うものである。プロトコルの機能を省いても、この段階はなくならない
