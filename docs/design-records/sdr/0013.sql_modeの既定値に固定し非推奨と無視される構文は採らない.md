# sql_mode の既定値に固定し、非推奨と無視される構文は採らない

## Motivation

MySQL の字句・構文には、サーバー変数 `sql_mode` で挙動が切り替わる箇所 (二重引用符の意味、バックスラッシュのエスケープ、`NOT` の優先順位、`||` の意味) がある。また、後方互換のためだけに残っている別表記や、MySQL 自身が読み飛ばす構文もある。これらをどこまで写すかを決める必要があった

## Decisions

- `sql_mode` に依存する分岐は、8.4 の既定値の側に固定する
  - `"` は文字列の引用符、バックスラッシュのエスケープは有効、`NOT` は低い優先順位
  - `||` は採用しない (既定では OR の別表記、`PIPES_AS_CONCAT` では連結で、どちらも採らない)
- 8.4 で非推奨の別表記は採らない
  - `&&`、`||`、`!`、`$` で始まる識別子、`N'...'`、`BINARY expr`、`INSERT DELAYED`、`SQL_CALC_FOUND_ROWS`
- MySQL 自身が読み飛ばす構文は採らない
  - カラム定義内の `REFERENCES`、外部キーの `MATCH`、`DROP TABLE ... RESTRICT | CASCADE`

## Context

MineSQL は `sql_mode` を持たない。既定値以外の挙動を選べる必要がないので、分岐を残す理由がない

非推奨の別表記は、将来の MySQL で消える構文である。MySQL 自身が読み飛ばす構文は、書いても挙動が変わらない。どちらも「従っても挙動が変わらない、または将来消える」ものなので、互換を保つ意味がない。「MySQL の規則に従う」([SDR-0007](./0007.SQLパーサーはMySQLの構文規則に従う.md)) の例外として、理由つきで外す
