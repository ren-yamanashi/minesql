# X Plugin

MySQL X Pluginは、従来のSQL言語に加えて、ドキュメントストアとリレーショナルデータの両方で利用できる使いやすいCRUD形式のプログラミングインターフェースを通じて、MySQLのACIDに準拠したデータストレージ機能を公開することを目的とした機能群および拡張プロトコルを実装している

- ドキュメントモデルのインターフェースは、MySQLの既存のSQL機能の上のレイヤーとして実装される
- プロトコルとクライアントライブラリは、プラグインによって実装されるハイレベルなインターフェースを提供する
- このプラグインは、ドキュメントモデルのリクエストからSQLへのマッピングに必要なすべての処理を担う

## 要件

- 一般的な要件
  - JSON データの保存および取得を行うため、ドキュメント指向の CRUD インターフェースを実装すること
  - ユーザーが上位レベルの API を介してドキュメントテーブルを作成できるようにし、背後にある SQL 階層の実装詳細を隠蔽 (ユーザーが意識しなくて済むように) すること
  - ユーザーが SQL を記述することなく、ドキュメントテーブルへのデータ保存や基本的なクエリの実行を行えるようにすること
  - 通常の MySQL 接続と同等の機能を提供する拡張 X プロトコルを実装すること

- 接続
  - getCapabilities メッセージを使用して自身の機能を通知しなければならない (MUST)
  - クライアントが setCapabilities メッセージを使用して自身の機能を通知できるようにしなければならない (MUST)
  - ユーザーが他のセッションを強制終了（kill）できるようにしなければならない (MUST)
  - 特権ユーザーがプラグインに接続されているセッションを閲覧できるようにしなければならない (MUST)
  - 拡張プロトコルに対応していない MySQL クライアントが誤って X プラグインに接続を試みた場合、適切に処理されなければならない (SHOULD)
  - SSL 接続をサポートしなければならない (MUST)

- 認証
  - ネットワーク上にパスワードを平文で送信しない、チャレンジ/レスポンス型の認証方式を用いてクライアント認証を行わなければならない
  - MySQLのユーザーシステム（mysql.user）を使用し、それに従わなければならない

- クエリ / DML インターフェイス
  - ユーザーが、従来通り従来のSQLコマンドを実行できるようにしなければならない
  - ユーザーが、ドキュメントモデルのCRUDコマンドを実行できるようにしなければならない
  - すべての操作は、成功した場合にOKメッセージを返さなければならない
    - メッセージには、影響を受けた行数、GTID（有効な場合）、その他のメタデータを含める必要がある

- SQL インターフェイス
  - SQL 文を実行できること

- リザルトセット・インターフェイス
  - 実行されたステートメントからメタデータおよびレコードを取得できなければならない
  - ユーザーは、名前などの情報を省略した簡略化版のメタデータを返すようサーバーに要求できなければならない

- ドキュメントテーブル・インターフェイス
  - ユーザーが複雑な記述を伴う SQL を書くことなく、ドキュメントの保存に適したテーブルを作成できなければならない
  - SQL の基礎知識がなくても、ドキュメントのフィールドに対してインデックスを作成できなければならない
  - インデックスを削除できなければならない
  - 既存のインデックス一覧を表示できなければならない
  - 既存のドキュメントテーブル一覧を表示できなければならない
  - テーブルを削除できなければならない

- CRUD インターフェイス - Insert
  - 事前に作成されたドキュメントテーブルに対して、JSON ドキュメントを挿入できなければならない
  - ドキュメントのオブジェクト識別子または主キーとして、`_id` という名前で事前定義されたフィールドを使用しなければならない
  - オブジェクトの識別子は、テーブル内で一意でなければならない
  - クライアント側からオブジェクト識別子が指定されていない場合は、プラグイン側で一意な識別子を生成しなければならない

- CRUD インターフェース - (Find)
  - ユーザーが指定した式に内容が一致する JSON ドキュメントをクエリできなければならない
  - 0 行以上の結果セットを、メタデータとともに返さなければならない
  - CRUD インターフェースを介してリレーショナルテーブルの SELECT ができなければならない

- CRUD インターフェース - (Update)
  - オブジェクト ID またはクエリ式によって特定された、保存済み JSON ドキュメントを更新できなければならない
  - CRUD インターフェースを介してリレーショナルテーブルのカラムを更新できなければならない

- CRUD インターフェース - (Delete)
  - オブジェクト ID またはクエリ式によって特定された、保存済み JSON ドキュメントを削除できなければならない
  - CRUD インターフェースを介してリレーショナルテーブルから行を削除できなければならない

- 非機能要件
  - MySQLのユーザーアカウントを使用して認証を行わなければならない
  - プラグインの基本的なステータス監視を可能にしなければならない
  - MySQLのユーザーアカウント制限（期限切れのパスワードや、ロックされたアカウントへのログイン拒否など）に準拠しなければならない
  - プラグインが使用するものとまったく同じテーブルレイアウトに従っていない限り、ユーザーが手動で作成したコレクションでドキュメントCRUDインターフェースが機能することは「要件ではない」
    - プラグインはコレクションに対して特定のテーブルレイアウトを使用するため、ユーザーがそれらを誤って模倣しようとした場合、ドキュメントCRUDインターフェースを使用した際の結果は未定義となる
    - ただし、そのようなテーブルであってもリレーショナルCRUDインターフェースでは完全にサポートされる
  - mysqldump や mysql などの従来のツールを使用して、スキーマとそのデータをバックアップおよび復元できるようにする必要がある
  - パフォーマンスの点において、一般的な期待値としては、プラグイン経由で実行される操作は、従来のMySQLプロトコルを使用して現在のクライアント接続パイプライン経由で実行された場合と同等のパフォーマンスを持つことである
    - したがって、プラグインは一般的な条件下での一般的な操作において、可能な限りそのパフォーマンスに近づけるよう努めるものとする

### ドキュメントテーブルについて

- ドキュメントテーブル (コレクション) というのは、JSON 型を部品として使った、特定の形のテーブル
  - X Plugin の create_collection が作る、スキーマが決め打ちされた普通の InnoDB テーブル
  - doc JSON — ドキュメント全体をこの 1 カラムに入れる
  - _id — doc の $._id から抽出される生成カラムで、これが主キー
  - _json_schema + CHECK 制約 — ドキュメントのスキーマ検証用
