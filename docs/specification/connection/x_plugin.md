# X Plugin

MySQL X Plugin は、従来の SQL 言語に加えて、ドキュメントストアとリレーショナルデータの両方で利用できる使いやすい CRUD 形式のプログラミングインターフェースを通じて、MySQL の ACID に準拠したデータストレージ機能を公開することを目的とした機能群および拡張プロトコルを実装している

- ドキュメントモデルのインターフェースは、MySQL の既存の SQL 機能の上のレイヤーとして実装される
- プロトコルとクライアントライブラリは、プラグインによって実装されるハイレベルなインターフェースを提供する
- このプラグインは、ドキュメントモデルのリクエストから SQL へのマッピングに必要なすべての処理を担う
- 以下の「要件」は [WL#8338](https://dev.mysql.com/worklog/task/?id=8338) に書かれた MySQL の X Plugin の要件の訳で、MineSQL がそのうちどれを採るかは [MineSQL での対応範囲](#minesql-での対応範囲) に示す

## 要件

- 一般的な要件
  - JSON データの保存および取得を行うため、ドキュメント指向の CRUD インターフェースを実装すること
  - ユーザーが上位レベルの API を介してドキュメントテーブルを作成できるようにし、背後にある SQL 階層の実装詳細を隠蔽 (ユーザーが意識しなくて済むように) すること
  - ユーザーが SQL を記述することなく、ドキュメントテーブルへのデータ保存や基本的なクエリの実行を行えるようにすること
  - 通常の MySQL 接続と同等の機能を提供する拡張 X Protocol を実装すること

- 接続
  - `CapabilitiesGet` メッセージを使用して自身の機能を通知しなければならない
  - クライアントが `CapabilitiesSet` メッセージを使用して自身の機能を通知できるようにしなければならない
  - ユーザーが他のセッションを強制終了 (kill) できるようにしなければならない
  - 特権ユーザーがプラグインに接続されているセッションを閲覧できるようにしなければならない
  - 拡張プロトコルに対応していない MySQL クライアントが誤って X プラグインに接続を試みた場合、適切に処理されるべきである
  - SSL 接続をサポートしなければならない

- 認証
  - ネットワーク上にパスワードを平文で送信しない、チャレンジ / レスポンス型の認証方式を用いてクライアント認証を行わなければならない
  - MySQL のユーザーシステム (mysql.user) を使用し、それに従わなければならない

- クエリ / DML インターフェース
  - ユーザーが、これまで通り従来の SQL コマンドを実行できるようにしなければならない
  - ユーザーが、ドキュメントモデルの CRUD コマンドを実行できるようにしなければならない
  - すべての操作は、成功した場合に OK メッセージを返さなければならない
    - メッセージには、Affected Rows、GTID (有効な場合)、その他のメタデータを含める必要がある

- SQL インターフェース
  - SQL ステートメントを実行できること

- リザルトセット・インターフェース
  - 実行されたステートメントからメタデータおよびレコードを取得できなければならない
  - ユーザーは、名前などの情報を省略した簡略化版のメタデータを返すようサーバーに求められなければならない

- ドキュメントテーブル・インターフェース
  - 必要な形式の SQL をユーザーが書かなくても、ドキュメントの保存に適したテーブルを作成できなければならない
  - SQL の基礎知識がなくても、ドキュメントのフィールドに対してインデックスを作成できなければならない
  - インデックスを削除できなければならない
  - 既存のインデックス一覧を表示できなければならない
  - 既存のドキュメントテーブル一覧を表示できなければならない
  - テーブルを削除できなければならない

- CRUD インターフェース - Insert
  - 事前に作成されたドキュメントテーブルに対して、JSON ドキュメントを挿入できなければならない
  - ドキュメントのオブジェクト識別子または主キーとして、`_id` という名前で事前定義されたフィールドを使用しなければならない
  - オブジェクトの識別子は、テーブル内で一意でなければならない
  - クライアント側からオブジェクト識別子が指定されていない場合は、プラグイン側で一意な識別子を生成しなければならない

- CRUD インターフェース - Find
  - ユーザーが指定した式に内容が一致する JSON ドキュメントをクエリできなければならない
  - 0 行以上のリザルトセットを、メタデータとともに返さなければならない
  - CRUD インターフェースを介してリレーショナルテーブルの SELECT ができなければならない

- CRUD インターフェース - Update
  - オブジェクト ID またはクエリ式によって特定された、保存済み JSON ドキュメントを更新できなければならない
  - CRUD インターフェースを介してリレーショナルテーブルのカラムを更新できなければならない

- CRUD インターフェース - Delete
  - オブジェクト ID またはクエリ式によって特定された、保存済み JSON ドキュメントを削除できなければならない
  - CRUD インターフェースを介してリレーショナルテーブルから行を削除できなければならない

- 非機能要件
  - MySQL のユーザーアカウントを使用して認証を行わなければならない
  - プラグインの基本的なステータス監視を可能にしなければならない
  - MySQL のユーザーアカウント制限 (期限切れのパスワードや、ロックされたアカウントへのログイン拒否など) に準拠しなければならない
  - プラグインが使用するものとまったく同じテーブルレイアウトに従っていない限り、ユーザーが手動で作成したコレクションでドキュメント CRUD インターフェースが機能することは「要件ではない」
    - プラグインはコレクションに対して特定のテーブルレイアウトを使用するため、ユーザーがそれらを誤って模倣しようとした場合、ドキュメント CRUD インターフェースを使用した際の結果は未定義となる
    - ただし、そのようなテーブルであってもリレーショナル CRUD インターフェースでは完全にサポートされる
  - mysqldump や mysql などの従来のツールを使用して、スキーマとそのデータをバックアップおよび復元できるようにする必要がある
  - パフォーマンスの点において、一般的な期待値としては、プラグイン経由で実行される操作は、従来の MySQL プロトコルを使用して現在のクライアント接続パイプライン経由で実行された場合と同等のパフォーマンスを持つことである
    - したがって、プラグインは一般的な条件下での一般的な操作において、可能な限りそのパフォーマンスに近づけるよう努めるものとする

### ドキュメントテーブルについて

- ドキュメントテーブル (コレクション) というのは、JSON 型を部品として使った、特定の形のテーブル
  - X Plugin の `create_collection` が作る、スキーマが決め打ちされた普通の InnoDB テーブル
  - カラム構成
    - `doc` (JSON 型): ドキュメント全体をこの 1 カラムに入れる
    - `_id`: `doc` の `$._id` から抽出される生成カラムで、これが主キー
    - `_json_schema` + CHECK 制約: ドキュメントのスキーマ検証用
